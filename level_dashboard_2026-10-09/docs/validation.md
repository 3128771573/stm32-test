## DHT 一直 E3 N0 的根因与修复

用户实测：TRY 持续增加，PA1 接地后 P0/E5，三针模块直连后仍 E3 N0 P1。
检查实际 stm32f10x_exti.c 发现 EXTI_Init(LineCmd=DISABLE) 只关掩码，不配置触发寄存器。
原驱动在此分支初始化，随后只打开 IMR，导致 FTSR 的 EXTI1 位一直为 0，传感器下降沿无法触发接收。
修正为 LineCmd=ENABLE 先完成下降沿配置，再手动屏蔽 IMR，接收前启用。

旧临时测试把 EXTI_Init 替换为空函数并直接调用 ISR，验证了脉冲解码，但漏掉触发寄存器配置，不能作为此前 EXTI 链路正确的证据。
本次从项目原厂库提取实际 EXTI_Init 函数，仅把地址临时变量/转换改成 uintptr_t 以适配 64 位测试宿主。
对照相同函数的初始化结果：旧版 FTSR=0、IMR=0；修复版 FTSR=2、IMR=0。
回归脉冲必须经过 FTSR 与 IMR 门控才能进入真实 DHT ISR，完整帧、超时、错误脉冲与恢复测试通过。
AC5 编译 0 错误、0 警告，Code=15972、RO=2032、RW=200、ZI=3392 字节。
修复确切的初始化缺陷；实际模块通信恢复仍需用户烧录新 hex 验收。

## 开机 SYSTEM POST 逐项自检

去掉按固定时长增长的动画进度，改为按结果推进。第一页依次检查 RCC 时钟配置、SysTick 寄存器并等待一次真实毫秒节拍、TIM2 配置并等待计数达到 100µs、OLED I2C ACK、MPU6050 初始化及五个配置寄存器回读。第二页等 DHT11 完成首帧及数据校验，再读 W25QXX JEDEC / 容量，并由 Logger 实际扫描末尾 64KB 日志区域；最后核对编码器输入以及 RGB PWM / 蜂鸣器 GPIO 的配置寄存器。

每行先显示 `TEST`，实际检查结束并将对应状态刷新到 OLED 后才检查下一项。`CHECKS n/10` 是已得出结果的数量，包含 `ERR` / `SKIP`，不是成功率；进度条只表示这些结果项，Flash 扫描阶段使用 `Logger_ScanProgress()` 的真实已读记录数。DHT `WAIT` 期间真实发起一次采集；`CRC OK` 只在首帧有效时出现。Flash 的 `DONE` 表示槽位遍历完成且没有总线错误或未知格式锁定；CRC 无效、未提交的条目依照原日志规则跳过，不作为有效记录计入。DHT 超时、Flash 未识别、其他格式日志触发 `LOCK` 都如实显示，均不阻止进入主仪表。日志检查只读，不写入或擦除 Flash。`CFG` 仅核对引脚和定时器配置，不能测量 LED 实际亮度、蜂鸣器音量或旋转编码器电气响应。

复核 POST 时序时修复两处问题：DHT11 后台任务只在传感器初始化完成后启动；Flash 日志扫描只在 `LOG AREA` 的 `SCAN` 提示实际刷新完成后开始。扫描完成后的状态判断也覆盖 `DONE`、`LOCK`、`SKIP`，避免正常扫描提前结束被误报为 `ERR`。SysTick 或 TIM2 自检失败时，DHT11 初始化被跳过，主循环也不会启动未初始化的 DHT11 任务。

Keil ARM Compiler 5.06 update 7 工程构建：0 错误、0 警告；Code=23816、RO-data=2496、RW-data=352、ZI-data=3992 字节。链接图的 Total ROM Size 为 26404 字节、Total RW Size 为 4344 字节。Intel HEX 共 26404 个数据字节，范围 0x08000000–0x08006723；所有记录校验和正确，包含 EOF 记录，栈指针 0x200010F8 按 8 字节对齐，复位向量 0x08000105 指向 Thumb 代码，未越过 64KB Flash。SHA-256：`3A42E5D99005035FB4D58FE6974DB2CF6677E7A172BC2C8395E51E60AC014A83`。新 POST 未增加全局显存缓冲区，但实物 OLED、DHT11、Flash 和灯效结果仍待烧录验收；本次没有把编译或固件结构检查冒充为硬件通过。改动前 HEX 保留在 `../MDK-ARM/Obj/level_before_post.hex`。

## 2026-10-10 稳定性复核与界面收简

I2C 起始会检查释放后的 SCL/SDA 电平，每个传输时钟核对 SCL 实际升高，并以 1ms 与有限循环双重限制等待。测试直接编译真实 `i2c.c`，在临时外设桩中覆盖正常 ACK、无设备、SDA 持续拉低、SCL 持续拉低和解除故障后重新探测；故障线不再误报在线，读写返回错误。开机 OLED 缺席时保留板载 LED 闪码，每组闪码后重新探测，屏幕接回后再进入 POST。

## 2026-10-10 开机时长会话版（20261010E）
