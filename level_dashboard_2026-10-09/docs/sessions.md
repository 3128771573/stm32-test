# 每次开机时长与历史会话

当前工作版为 `20261010E`，不使用 RTC，也不记录日期。STM32 用现有 SysTick 毫秒计数计算本次运行时长，无需校时、电池或额外接线。

## 查看本次和以前的运行时长

- `RUNTIME` 页实时显示本次开机已运行多久、开机编号和 MCU 复位原因；下方显示上一轮已保存的最小时长。
- `SESSIONS` 页会自动进入浏览。旋转编码器查看各次开机，顶部 `1/N` 是最近一次；当前会话显示实时运行时长，过去会话显示 `>=` 保存时长。继续向两端旋转可退出浏览。
- 首页切到 DEBUG 后继续向右，便能进入 RUNTIME；再右转进入 SESSIONS。只有旋转编码器即可完成查看。

## 突然断电时的精度

程序每分钟向 W25QXX 保存一次存活检查点，并在新开机时保存一条 BOOT 记录。突然断电时 MCU 来不及写最终时长，所以历史会话显示最后一个检查点，前面的 `>=` 表示“至少运行这么久”；实际运行时长通常最多比显示值多约一分钟。若没有任何检查点，页面显示 `NO CHECKPOINT`，不猜测总时长。有序按复位或重启时也只能读取最近的检查点，不能把它当成完整精确时长。

事件区有 256 条记录，含 4KB×2 扇区循环使用。BOOT 与每分钟的检查点共用容量，因此连续运行时保留窗口约数小时；快速反复重启会更快覆盖早期会话。事件数据有 CRC 与提交标记；已存在未知格式的数据会锁定保护，不自动擦除。POST 中 EVENT 显示 `DONE`，才代表本次开机记录已写入并读回确认。若 W25QXX 未接或识别失败，当前时长仍正常显示，但无法保存和浏览历史会话。

## 烧录后验收

1. 连接好 W25QXX，开机等待 POST 的 EVENT 显示 `DONE`。
2. 转到 RUNTIME，确认开机编号和时长逐秒递增。
3. 转到 SESSIONS，查看最新记录显示 `CURRENT SESSION` 及实时运行时长。
4. 运行一分钟以上后断电重启；等待新一次 EVENT `DONE`，进入 SESSIONS，最近一条应为新会话，向旧记录旋转一格应看到上一会话的 `>=` 时长检查点。
5. 若历史时长没有更新，先确认每次 POST 的 EVENT 都为 `DONE`、系统页 Flash 状态为 READY；不要对未知 Flash 内容执行格式化。

编译和软件验证记录见 [validation.md](validation.md)。实际板上 Flash 写入、断电时序仍需实物验收。
